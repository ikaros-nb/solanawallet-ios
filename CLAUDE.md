## Build & test commands

Open the **workspace**, not the project — the workspace bundles the sibling SwiftPM packages alongside `SolanaWallet.xcodeproj`:

```bash
open SolanaWallet.xcworkspace
```

`AllTests.xctestplan` aggregates `CoreInfrastructureTests` (SPM) and `SolanaWalletIntegrationTests` (Xcode XCTest target). Both use the Swift `Testing` framework (`@Suite`, `@Test`), not XCTest.

```bash
# Build (workspace required so SPM packages resolve)
xcodebuild -workspace SolanaWallet.xcworkspace -scheme SolanaWallet \
  -destination 'platform=iOS Simulator,name=iPhone 17'

# Full test plan
xcodebuild test -workspace SolanaWallet.xcworkspace -scheme SolanaWallet \
  -testPlan AllTests -destination 'platform=iOS Simulator,name=iPhone 17'

# CoreInfrastructure unit tests only (no simulator needed)
cd CoreInfrastructure && swift test

# Single Swift Testing test by name
cd CoreInfrastructure && swift test --filter 'BorshCoderTests'
```

`SolanaWalletIntegrationTests` exercises real Keychain + Secure Enclave APIs; it must run on a simulator/device, **not** via `swift test`.

## Lint & format

Run `lefthook install` once. The pre-commit hook auto-runs SwiftFormat and `swiftlint --strict` — any warning blocks the commit. Don't bypass with `--no-verify`; fix the warning instead. `analyzer_rules` (`unused_declaration`, `unused_import`) only fire under `swiftlint analyze` against a compiled build.

## Local Solana RPC (Surfpool)

`Config/Debug.xcconfig` sets `SOLANA_RPC_ENDPOINT = http://localhost:8899` (Surfpool). The endpoint is injected via xcconfig → `Info.plist` `SolanaRpcEndpoint` key → `AppDependencies.solanaRpcEndpoint()`. Fallback `http://localhost:8899` keeps previews and unit tests working when `Bundle.main` is the test/preview bundle. Network is hardcoded to `.devnet`.

The `test-ledger/` directory at the repo root is Surfpool's on-disk validator state — don't commit changes to it, and don't delete it without checking that nobody is mid-session.

## Architecture

Thin app target (`SolanaWallet/`) plus six SPM packages: `CoreDomain` (incl. `CoreEntities`), `CoreInfrastructure`, `CorePresentation`, `FeatureDashboard`, `FeatureVault`, `FeatureWallet`. The app shell is the composition root and the only place that knows about both sides.

**Dependency rule**: features depend on `CorePresentation` (CoreUI) and `CoreDomain` only. They do **not** depend on `CoreInfrastructure`. Concrete services are injected through SwiftUI `@Environment` values declared in `FeatureWallet/WalletDependencies.swift`.

### App bootstrap & navigation

`SolanaWalletApp.init()` calls `AppDependencies.make()` exactly once (fatal-errors on failure — the wallet security stack must initialize). `RootView` reads `AppState.isOnboarded` to choose between `WelcomeAssembly.make()` and `MainTabView`. `AppState.rehydrate(from:)` reads the public key from Keychain on launch.

Each feature exposes a public `*Assembly.make()` entry point that owns its own `NavigationStack` + `WalletNavigator` and injects flow-scoped state via `.environment(...)`. **Routes are `Hashable` enums** (`WelcomeRoute`, `BiometryRoute`, `RecoveryPhraseRoute`) — never put secrets like `SecureSeedPhrase` in a route, because `NavigationPath` may be persisted via state restoration. `OnboardingSession` holds the live phrase instead.

## Conventions

- **Logging**: `AppLog.logger(for: "Category")` (subsystem: `com.ikaros.SolanaWallet.coreinfrastructure`). Use `privacy: .public` only for non-sensitive fields.
- **Debug-only RPC logging**: `SolanaSwiftLoggerImpl` and `LoggingNetworkManager` are wired behind `#if DEBUG` in `AppDependencies` — don't add ad-hoc `print`s.
- **Identifier naming**: `Pubkey` is a base58 `String` alias, `Lamports` is `UInt64`, `TransactionSignature` is `String`. Don't reintroduce raw types in domain code.
- **File headers**: auto-generated by Xcode and preserved by SwiftFormat (`--header ignore`). Keep them on new files.
